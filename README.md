## 如何启动

需要先装好 **Go 1.27+** 和 **Node.js 22.18+ / 24.12+**，
各自执行 `go version`、`node -v` 能打印版本号即可。

```bash
# 终端 1：启动后端
cd server
go run .

# 终端 2：启动前端（后端要保持运行）
cd web
npm install     # 首次运行需要
npm run dev
```

浏览器打开 <http://localhost:5173>。

> **完整的运行说明见 [运行说明.md](./运行说明.md)** —— 里面有逐步的验证清单、
> 环境变量说明、以及国内网络常见问题（Go 代理、终端中文乱码、PowerShell 执行策略）的处理办法。

## 已实现功能
- 公共聊天室
- 成员加入、退出提醒
- 历史消息持久化保存（SQLite，带条数上限，不会无限增长）
- 断线自动重连（指数退避），重连时按 `since` 只补错过的消息
- 正在翻历史时来新消息不打断，改为提示「N 条新消息」，点一下跳到第一条未读
- 移动端适配（窄屏侧栏变抽屉、安全区处理）
- 切换暗色模式
- 聊天气泡宽度自适应，昵称按哈希分配颜色

## 已知问题

1. **重名用户可以同时在线。**
   服务端的在线列表以「连接对象」为键，昵称只用于显示和判断"这条是不是我发的"。
   两个人取同一个昵称都能进来，成员列表里只会显示一个名字。

2. **没有身份验证，昵称可以随便填。**
   服务端只做非空和长度校验，任何人带上任意昵称都能连上来。
   真实产品需要会话令牌之类的机制。

3. **历史消息只推最近 100 条，没有"向上翻页"。**
   `GET /api/messages` 支持 `since` 参数，但语义是"给我比它**更新**的"，
   用来翻更早的消息需要改成 `before=<id>`。

4. **在线状态没有独立的"离开"通知。**
   完全依赖 WebSocket 连接是否还活着，心跳周期 54 秒，
   所以最坏情况下要 60 秒才能发现有人掉线。

5. **服务端没有完整的优雅关闭。**
   存储层有 `Close()`，进程正常退出时数据库会把 WAL 落盘并释放文件；
   但没有监听系统信号，Ctrl+C 时不会主动通知在线用户，也不会等正在写库的操作收尾。

6. **数据库上限是固定值（1000 条），不可配置。**
   超出的最老消息会被直接删除，没有归档或导出。
